# Limitations and remaining work
**Environment-limited (not done here):** Docker image build/run; KiCad ERC (KiCad 8); live distributor API and real LLM calls (credentials; mocks only); real-browser E2E and WebGL rendering of the 3D view; GitHub CI run; LICENSE (owner's choice).
**Product limits:** PCB layout is a single row of through-hole parts with simple 2-layer routing for small boards (spacing is optimizable, nothing else); no ground planes, high-speed, thermal or power-integrity analysis; the 3D view is approximate (bounding boxes and typical package heights, not KiCad 3D models); wires are drawn as orthogonal links to a net label, positions are view-only; no logic gates, switching regulators, or op-amp offset/bandwidth/slew; parts are generic models with generic footprints and unverified ratings; component library has 12 generic entries plus whatever users enter (user data is labelled user-entered and never verified); optimization covers the LED indicator (power), the 3-part divider (target voltage) and PCB area only; AI edits are limited to set_value/add/remove/set_pin operations and a few deterministic rules.
**Accuracy:** SPICE models are generic; template ratings (1 A, 100 mA) are assumptions. Rating checks use the DC operating point (transient peaks not checked). The regulator assumes 2 V dropout, 50 mOhm output resistance, no quiescent current or current limit; junction temperature is never computed without a datasheet theta_JA. Transistor pad numbering follows the KiCad symbol and must be checked against the real part. Passing checks, DRC or export is never a safety or manufacturability claim.
**Operational:** background jobs use an in-process thread pool (lost on restart); rate limiter and AI quota are per-process and in memory; datasheets are stored on the server filesystem; dev-tool npm advisories exist (production deps: 0).
